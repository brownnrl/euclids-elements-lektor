# Content model

The conceptual model and the places it diverges from vanilla Lektor.

## URL hierarchy

```
/                                               root (Introduction)
/elements/                                      master Table of Contents (toc model)
/elements/prematter/                            prematter index
/elements/prematter/<leaf>/                     prematter leaf (about / Euclid / web / …)
/elements/books/                                book index (auto-generated by section_index?)
/elements/books/bookI/                          book intro page (book model)
/elements/books/bookI/definitions/              section_index — model: section_index, child_model: definition
/elements/books/bookI/definitions/defI1/        leaf — model: definition
/elements/books/bookI/definitions/defI15_18/    hidden group — model: definition_group
/elements/books/bookI/postulates/post1/         leaf — model: postulate
/elements/books/bookI/commonnotions/cn1/        leaf — model: commonnotion
/elements/books/bookI/commonnotions/cn1_5/      hidden group — model: commonnotion_group
/elements/books/bookI/propositions/propI1/      leaf — model: proposition
/other-works/<slug>/                            Joyce's republished tutorials and
                                                geomlib's own site — model: other_work
/geomlib/                                       geomlib landing + Using + Joyce's 1996
                                                applet archive + construction tables
```

Three depth levels under each book: **section** (definitions/postulates/commonnotions/propositions) → **leaf** (e.g. propI7) → optional inline anchors (#guide, #cor).

## Models

### `book`

Fields: `title`, `short_description` (one-liner for the master TOC), `body` (markdown — the book intro Guide).

Children are four `section_index` pages (one per section type). The `book.html` template auto-lists them in canonical order (Definitions → Postulates → Common Notions → Propositions → Guide).

### `section_index`

Fields: `title`, `child_model` (one of `definition` / `postulate` / `commonnotion` / `proposition`), `body` (optional intro markdown).

The `child_model` field tells the template which children to enumerate. The template filters children by `F._model == this.child_model`, which is also why bundle-group pages stay out of the list — they have a different model.

### Leaf models (`definition`, `postulate`, `commonnotion`, `proposition`)

Common fields:

| Field | Type | Notes |
|---|---|---|
| `title` | string | "Definition 1", "Proposition 7" |
| `short_label` | string | "I.Def.1", "I.7" — used by footer nav and master TOC |
| `order` | integer | Sort key; siblings query orders by it |
| `statement` | html | The one-line claim; stays `html` so inline `<i>` works in cross-record contexts (it's pulled into section_index dd's and the master TOC) |
| `red_highlight` | boolean | Joyce's `<font color=bb0033>` |
| `group` | string | Slug of a sibling `definition_group` / `commonnotion_group` page (bundled-source pages only) |

`proposition` adds two markdown fields:

| Field | Renders | Notes |
|---|---|---|
| `proof` | inside theorem box, after statement | Construction + proof, with marginal `<div class="just">` annotations and trailing `<div class="qed">Q.E.F.</div>` |
| `body` | below theorem box under `<h2 id="guide">Guide</h2>` | Commentary; commonly has `#### …` subsections |

For non-proposition leaves there's a single `body` (markdown) that becomes the Guide; the theorem box is built entirely from `title` + `statement`.

### Group models (`definition_group`, `commonnotion_group`)

Fields: `title`, `body` (markdown).

Used when one source HTML page bundles multiple leaves (defI15.html holds defs 15-18; cn.html holds cn1-5). One group page holds the shared guide markdown; the bundled leaves each carry `group: <group-slug>` and an empty body, and re-render the group's content from their own URL.

`_hidden: yes` keeps them out of `parent.children` queries and tree traversal. Section index also filters by model name as a second safeguard.

## The bundle pattern

This is the biggest divergence from "one URL = one record" and is worth understanding before touching content.

### Why

Some bundled-source pages have a single combined discussion that can't be cleanly split:

- defs **15-18** (circle / center / diameter / semicircle)
- defs **11-12** (obtuse / acute angle)
- defs **13-14** (boundary / figure)
- defs **20-21** (trilateral by sides / by angles)
- cn **1-5** (the 5 common notions)

The original site presents all bundled definitions on one page. The Lektor rebuild preserves a discrete URL per definition (so citations like `I.Def.16` still map to a `/defI16/` slug), and on each URL renders the full bundled content.

### How

1. Each bundled leaf has empty `body` and `group: <slug>` pointing at a sibling group page.
2. A hidden sibling folder with `_model: definition_group` (or `commonnotion_group`) holds the actual shared markdown body.
3. The leaf template detects `this.group`, looks up the group via `site.get(this.parent.path ~ '/' ~ this.group)`, finds all sibling members via `this.parent.children.filter(F.group == this.group).order_by('order')`, and renders:
   - one theorem box per bundle member (definitions) **or** one combined box with a numbered statement list (common notions)
   - then the group's body as the Guide section

The hidden group page still gets a URL (its own template renders a minimal landing), but section indexes filter it out via `F._model == this.child_model`.

## Inline HTML inside markdown

Lektor's Mistune does NOT process markdown inside raw HTML blocks. Anywhere a markdown body contains a `<figure>`, `<div class="just">`, `<blockquote class="axiom">`, etc., put plain HTML inside (use `<i>` for italics, `<a href>` for links). Failing to do this leaves `*x*` and `[X](Y)` rendering as literal text.

## Things that are vanilla Lektor

- Build via `lektor build --output-path build/`
- `_hidden: yes` and `_model: …` system fields
- `F.field` filter expressions in `children.filter(...)`
- Markdown field type rendered to HTML via Mistune
- Asset pipeline: `assets/css/`, `assets/js/`, `assets/img/` files appear under `build/` at the same path

## Things that diverge from vanilla

- **Two markdown body fields on proposition** (`proof` + `body`). The template renders them in different visual regions (inside vs. outside the theorem box).
- **`statement` stays `html` not `markdown`** so it embeds cleanly in `<dd>` cells of section_index and master TOC without `<p>` wrappers from the markdown renderer.
- **`short_label` and `order` are present on every leaf model**, used by the JS footer nav and master TOC.
- **Bundle pattern** (`group:` field + hidden `*_group` model) is custom — Lektor has no built-in notion of grouped records.
- **The JS footer (`assets/js/footer-nav.js`)** carries its own `proptable` / `booktable` for cross-section navigation. This duplicates information available in the content tree, but keeps the nav fast and client-side. See [conventions.md](conventions.md#footer-nav) for the maintenance burden.
- **The master `layout.html`** detects `this._model` to choose between three header shapes (imagemap + book title; imagemap only; stacked `Euclid's Elements / Book I`). It also walks `this.parent.parent` to find the book name for leaf pages.
- **Section index template filters out group models** via `{% if k._model == this.child_model %}`. Without that filter, bundle group pages would appear as ghost entries in the section listing.
